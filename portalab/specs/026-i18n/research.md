# Research — Internationalization & Localization (spec 026, roadmap step 10)

Re-validation of the earlier plan against the **ratified stack** (spec 001 plan: Python 3.12/FastAPI + PostgreSQL, React/TS SPA). The earlier "TypeScript end-to-end" baseline is **withdrawn**; contracts stay the same, only bindings change.

| # | Decision | Rationale | Alternatives rejected |
|---|---|---|---|
| R1 | **ICU MessageFormat is the single catalog syntax** (plural/select/gender, no concatenation) for both runtimes | FR-011/012; one catalog serves backend and frontend | gettext (weak plural/select), printf-style |
| R2 | **Frontend**: `react-intl`/`@formatjs/intl` (`intl-messageformat`) with native `Intl` (CLDR + tz in the browser) | Mature ICU runtime, no heavy bundle for CLDR | i18next (different syntax), custom renderer |
| R3 | **Backend rendering** (notifications, e-mail, AI answer language, exports, errors): `MessageRenderer` **port**; adapter chosen by a **spike with a shared golden-vector conformance suite** between candidates (`PyICU` binding vs pure-Python ICU MessageFormat parser + Babel plural rules). Contract tests run the same vectors against the JS runtime | Python has no first-class ICU MessageFormat in stdlib; avoid committing to a heavy native dep unproven | Picking `PyICU` blindly (system ICU dependency in the single image); a hand-rolled partial parser |
| R4 | **CLDR formatting on the backend: `Babel`** (dates, numbers, units, currency display, relative time, plural categories, first-day-of-week); frontend uses `Intl` | Babel bundles CLDR; offline; version pinned | Hand-rolled formats |
| R5 | **Time zones: stdlib `zoneinfo` + `tzdata` package**; instants stored `timestamptz` UTC (CD-012); rendering converts at the edge; wall-clock schedules keep `(local_time, tz)` + documented gap/overlap policy | DST-safe, offline, updated via dependency bump | `pytz`, storing local times |
| R6 | **Catalog storage**: base bundles are **files in the repo** per module/plugin (`locales/<lang>/<namespace>.json`, ICU strings) shipped in the image; **admin-managed overrides and admin content strings live in `i18n.catalog_entries`**; effective catalog = base ⊕ override, versioned by a content hash (`catalog_version`) used as ETag | Offline/air-gapped, review via Git for first-party, admin editability without redeploy | DB-only catalogs; third-party TMS dependency |
| R7 | **Tooling in CI** (`portalab-i18n` CLI + frontend script): extract keys, validate ICU syntax, check **placeholder/plural parity** across languages, detect unused/missing keys, pseudo-localization (`en-XA`, long strings, RTL `ar-XB`) for layout tests | FR-013/030 | Manual review |
| R8 | **`LocaleContext` resolved server-side per request** and returned by `GET /i18n/context`; SPA fetches once per session/change and mirrors to `<html lang dir>`; backend jobs obtain it through `LocaleResolver.for_user(user_id)` (recipient-based) | One resolution algorithm (C1) used by both | Client-only resolution |
| R9 | **Preferences** (`language`, `locale`, `timeZone`, `hourCycle`, `firstDayOfWeek`) are **user-tier keys in 020**; 026 declares them and defines `UserLocalePreferenceReader` / `I18nPolicyReader` ports that 020 implements (020 plan, ConfigPorts adapters). Language/locale/tz are `preference` class personal data in the 001 registry | CD-011, FR-036; avoids a second preference store | A separate `i18n.user_prefs` table |
| R10 | **Change propagation**: consume `admin.config_changed` (keys `i18n.*` and user `language|locale|timeZone`) to bump a `locale_epoch`; catalogs use ETag/`catalog_version`; own events `i18n.policy_changed`, `i18n.translation_updated` | Idempotent self-healing caches | Polling |
| R11 | **Multilingual content model** = contract + table helper (`LocalizedContentVersion` registry keyed by `(content_ref, language)`); content domains (011, 015, 014, …) own their content tables and call `ContentLocalizer` | FR-014..016, ownership | i18n owning all content |
| R12 | **External content**: provenance + `declared_language` kept by Connectors (005); i18n offers presentation-layer translation through an optional `TranslationProvider` port (no default implementation, off by default; OQ-127 deferred) | CD-014/026, FR-017..019 | Mandatory MT |
| R13 | **Search language-awareness (FR-020)** is a contract: `normalize_for_search(text, language)` (NFKC, casefold, diacritics folding via Unicode decomposition) + language list for analyzers; PostgreSQL FTS config mapping is owned by 008 | Keep engines in their owners | i18n owning the index |
| R14 | **Defaults for open questions** (kept as config, not architecture): OQ-126 baseline languages `en` (default) + `fr`; OQ-125 RTL capability built, no RTL language shipped enabled by default; OQ-128 wall-clock vs absolute is chosen **per schedule** with `absolute` default; OQ-129 unknown-language content shown as-is with marker; OQ-127 human-authored, MT optional later | Maintainer is French-speaking; flagged for product confirmation | Hard-coding |

No `NEEDS CLARIFICATION` remains; R3 is resolved by a time-boxed spike task (T004) with an explicit exit criterion.
