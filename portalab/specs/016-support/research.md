# Research — Support: tickets, incidents, feedback (spec 016, roadmap steps 13 + 17)

| # | Decision | Rationale | Alternatives rejected |
|---|---|---|---|
| R1 | **Three distinct aggregates** — `tickets`, `incidents`, `feedback_items` — separate tables, lifecycles and APIs. A ticket carries an optional `incident_id`; feedback conversion creates targets in their owning domains and keeps only a provenance link | Spec "strict conceptual distinctions", CD (one incident system: Support) | One polymorphic "issue" table |
| R2 | **Roadmap slicing**: *Slice A (step 13)* = incidents + the `support.incidents` port used by 006/025 + public surfacing + incident notifications/widgets; *Slice B (step 17)* = tickets, feedback, conversion, AI diagnosis flow. One module/plan, tasks ordered so Slice A can ship first | User roadmap places Incidents at step 13 and Support at step 17 | Two modules |
| R3 | **Workflows are declarative data** (`workflows`: states, transitions with guards on role/permission/assignee, required comment/fields); versioned; tickets pin `workflow_version`; baseline workflow `open → in_progress ⇄ waiting_user → resolved → closed` with `reopen` (resolved→open within a configurable window) and `cancel`. Admin may define custom workflows with the same closed schema (OQ-75 default). **No scripting**; reactions to transitions are events consumed by 019 | CD-010 (no second rules engine), FR-005 | Hard-coded states; free-form scripts |
| R4 | **Ticket types** = admin-defined records with custom-field schema (JSON Schema subset: text, long text, select, multi-select, number, boolean, date, user ref), required-field enforcement at creation naming the missing fields (FR-002), workflow binding, and per-field privacy (`requester_and_staff` vs `staff_only`) | FR-001..003 | EAV tables per field |
| R5 | **Attachments policy (OQ-77 default)**: allowlist by sniffed magic bytes (png, jpeg, webp, gif, pdf, txt/log, json, zip excluded), ≤ 10 MB, ≤ 5 per post, images re-encoded with EXIF stripped, everything else served only as download (`Content-Disposition: attachment`, `nosniff`, separate content origin path), stored in `core.blobstore` with sha256, retention with the ticket; optional `AttachmentScanner` port (none by default) | FR-004, security | Extension-based checks; inline rendering |
| R6 | **Incident lifecycle** `investigating → identified → monitoring → resolved` with an append-only update timeline; severity `minor|major|critical`; affected services by opaque id; created by Support/Admin, by 025 escalation (after validation when `requireValidation`) or by 006 via the port; dedup `(source, dedup_key)` | FR-008..010, 006/025 contracts | Reusing ticket states for incidents |
| R7 | **Surfacing to reduce duplicates**: `POST /tickets/precheck` returns open incidents matching the chosen service/type/keywords (deterministic: same service or text match) and permitted Wiki suggestions via `KnowledgeProvider` (011); works **without AI**. Incident banner also appears on the affected service page (006 incidents section) | FR-009/020 | AI-only deduplication |
| R8 | **Incident ↔ ticket policy (OQ-79 default)**: a ticket references at most one incident; agents link/unlink; **no ticket merging** (duplicates are linked to the incident); incident resolution never auto-resolves tickets but offers an audited **bulk action** (comment + optional transition) to Support | FR-010 | Auto-resolve; ticket merge |
| R9 | **Permission split (OQ-76 default)** via 003 grants: base roles `user` (`tickets.create`, own read/comment, `feedback.submit`, `incidents.read`), `support` (`tickets.read|assign|transition|internal_note`, `incidents.manage`, `feedback.review`), `moderator` (`feedback.review`, `feedback.convert` except contribution), `admin` (all + `support.configure`). **Sensitive (audited, confirmation where irreversible)**: reassigning across users, closing another user's ticket, viewing staff-only private fields/attachments, feedback conversion to contribution/project | FR-022/024 | Hard-coded roles |
| R10 | **Feedback**: admin-defined forms (`general|bug_report|feature_request|…`) with field schemas; submissions are `feedback_items` with status `new|reviewed|converted|dismissed`; never auto-ticketed. **Conversion** is explicit staff action through ports to owners — ticket (Support), contribution (013 `grant_contribution`, idempotent per feedback, anti-abuse owned by 013; OQ-78 default: staff decision only, no reward on submission), feature proposal (012/015), community project (015); provenance link kept; original never deleted | FR-011..016 | Support-local clones of targets |
| R11 | **AI diagnosis = contract + deterministic fallback**: Support defines the `DiagnosisFlow` steps (identify user → service state via 006 → permitted Wiki via 011 → analyze → propose → prefill) executed by the AI capability (018) **as the requesting principal**; the result is a `ticket_draft` (never a ticket) with a `diagnosis_run` transcript separating **real data** (state snapshots, article refs with `as_of`) from **AI interpretation**; submission is always an explicit user action. Without 018 the precheck (R7) is the flow's deterministic subset | FR-017..021, CD-003 | AI auto-submitting; AI-only creation path |
| R12 | **Privacy & retention**: requester's private custom fields and internal notes never visible to non-staff; staff see requester data only on a need basis (permission `tickets.read`); history append-only, not public; retention `support.ticketRetentionMonths` (24) via 021; erasure tombstones the requester and removes attachments/private fields per 021 participant | FR-023/026 | Open visibility to all staff |
| R13 | **Optimistic concurrency + single-transaction transitions**: each state change writes ticket row (`version`), history row, outbox event (and audit for sensitive) atomically; `If-Match` on mutations | FR-007 | Last write wins |
| R14 | **Notifications through 010 categories** `support.assignment|ticket_status|incident|feedback` (incident critical ⇒ alert); recipients limited to permitted audiences | FR-025 | Support-specific mailer |

No `NEEDS CLARIFICATION` remains; R3, R5, R8, R9, R10 are **plan defaults for OQ-75..79**.
