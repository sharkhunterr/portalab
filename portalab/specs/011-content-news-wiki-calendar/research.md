# Research — Content: News, Wiki, Calendar (spec 011, roadmap step 17)

| # | Decision | Rationale | Alternatives rejected |
|---|---|---|---|
| R1 | **Three modules, one shared capability**: modules `news`, `wiki`, `calendar` (own schemas/lifecycles/permissions) + `capabilities/content` (`ContentRef`, `LinkResolver`, sanitized Markdown pipeline, asset helper). Cross-domain links go through `ContentRef` and `LinkResolver`, never FKs | FR-025 distinctness + interconnection, 001 boundaries | One "content" table with a type column |
| R2 | **Markdown pipeline (OQ-51 default)**: source stored as Markdown (CommonMark + GFM tables/task lists + GitHub-style callouts `> [!NOTE|TIP|IMPORTANT|WARNING|CAUTION]` + fenced code + `mermaid` fences). Rendered **server-side** with `markdown-it-py` and sanitized with `nh3` (allowlist); result cached with `renderer_version`; **raw HTML disabled**, no iframes/embeds in v1 | FR-009/010 safety; one renderer for AI-readable text and UI | Client-side rendering only; allowing raw HTML |
| R3 | **Mermaid** runs client-side from the fenced source in `securityLevel: 'strict'` inside a sandboxed React component (no HTML labels, no click handlers); rendering failure shows the source block as code | Diagrams without executing untrusted markup | Server-side diagram rendering (heavy dependency) |
| R4 | **Images**: only portal assets (`portalab-asset:<id>`, uploaded via blobstore, magic-byte validated and re-encoded, EXIF stripped); external images blocked by default (`content.allowExternalImages=false`) to prevent tracking/leaks; external links get `rel="noopener noreferrer nofollow"` + visible external indicator | FR-010, privacy | Hot-linking arbitrary images |
| R5 | **Cross-links resolved at view time, not baked into cached HTML**: Markdown keeps `portalab://kind/id` hrefs with author-provided link text; the frontend batch-resolves via `POST /content/links/resolve` to annotate `ok|forbidden|archived|deleted|unavailable` per viewer (forbidden shows no title; archived/deleted degrade gracefully) | FR-026/027, per-viewer permissions with shared render cache | Embedding titles in HTML |
| R6 | **News lifecycle**: `draft → published` or `draft → scheduled → published` (job at `publish_at`, idempotent) `→ archived` (restorable); only drafts hard-delete; deleting archived content is sensitive + audited. **Audience (OQ-53 default)**: all authenticated users, optionally restricted to roles/groups/permission holders (003) evaluated server-side; no personal data in articles | FR-001..008 | Public (unauthenticated) news (CD-025) |
| R7 | **Featuring (OQ-54 default)**: window `featured_from/until` evaluated at read time; max `news.maxFeatured` (3); order by `feature_priority` then recency; overflow drops lowest from the featured surface only | FR-004 | Unlimited featured |
| R8 | **Wiki concurrency (OQ-52 default)**: optimistic **base-version** check; stale base ⇒ 409 with a server-side diff so the editor merges consciously; every save is an append-only revision; no locks, no realtime co-editing | Simple, safe, full history (FR-012) | Pessimistic locks; CRDT |
| R9 | **Wiki history & compare**: revisions append-only; compare is server-computed (line diff + word-level highlights, `difflib`/`diff-match-patch`-style) with textual markers (not color-only); **restore creates a new revision** referencing the restored version; history visibility requires `wiki.history.read` (default editors; Admin may widen) | FR-013/014/029 | Overwriting on restore |
| R10 | **AI/contextual help**: pages carry `readable_by_ai` and `help_keys[]`; `KnowledgeProvider.search` (implements 016's `support.knowledge`) and `HelpResolver.for_context(key, principal)` filter by the **asking user's** read permission; AI sees only what the principal can read (CD-003) | FR-016/017 | A separate AI knowledge index |
| R11 | **Calendar is federated and owns no items**: owners register `CalendarSource` providers (maintenance 006, News scheduled/featured, campaigns 014, community events 012 (owner confirmed 2026-10-01), deadlines from 013/015); each applies permission at source; per-source timeout; failing source ⇒ its `source_state` only (FR-030). **Deadlines (OQ-50 default)** are items of `type=deadline` supplied by owners — Calendar never invents them | FR-018..022 | Calendar-owned event table |
| R12 | **Time**: items carry UTC instants (+ reference tz for wall-clock items) or all-day dates; rendering via 026 (`LocaleContext`, first day of week, DST-safe); views month/week/list | FR-020, i18n | Local-time storage |
| R13 | **Reminders** are user-initiated opt-ins (`calendar.reminders`) fired by a job through 010 `send` (category `calendar.reminder`); at fire time the item is re-fetched from its source and permission re-checked (changed ⇒ updated text/time, removed ⇒ cancelled) | FR-023/024 | Calendar scanning all users |
| R14 | **Translations** through 026 `ContentLocalizer` (`news.article_translations`, `wiki.revision` translations) with source-language preservation and "not translated" indication | 026 FR-014..016 | Duplicated articles per language |

No `NEEDS CLARIFICATION` remains; R2, R6–R9, R11 are **plan defaults for OQ-50..54**.
