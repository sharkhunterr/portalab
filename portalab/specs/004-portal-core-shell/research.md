# Research — Portal Core Shell & Navigation (spec 004, roadmap step 9)

| # | Decision | Rationale | Alternatives rejected |
|---|---|---|---|
| R1 | **Single React SPA shell** with **React Router (data router)**; routes are lazy-loaded per module/feature (`React.lazy` + route `lazy`) | Persistent shell, no reset between modules (FR-002), code-splitting per module | Multi-page app; micro-frontends (overkill for a modular monolith) |
| R2 | **Navigation Manifest**: each module/plugin declares entries/commands/breadcrumb info in a typed manifest (`NavigationContribution`) registered through a core capability registry; the **backend assembles and permission-filters** it at `GET /me/navigation` | Dynamic nav (FR-005), rights-aware (FR-006), single source of truth, plugin-ready (FR-008) | Hard-coded frontend menu; client-side permission filtering as authority |
| R3 | **Filtering is authoritative server-side, hinted client-side**: manifest entry lists `required_permission` + optional resource kind; backend evaluates with `authz.authorize()` (batched per request); route guards re-check on data fetch (the API is the real boundary) | CD-002/FR-029 | UI as security boundary |
| R4 | **Enablement** = module/plugin registry state (module toggles from 020, plugin lifecycle from 023): disabled ⇒ entries absent **and** routes answer a standard "unavailable" state (FR-007/028) | Same truth for nav + routes | Separate nav toggles |
| R5 | **Ordering/grouping**: manifest provides `group`, `order_hint`; precedence: admin policy (`shell.navigation.layout`) > user personalization within policy (`shell.navigation.userOrder`) > manifest hint; ties broken deterministically by `(order_hint, plugin priority config, stable key)` (FR-009). Default for OQ-17 | Fits configuration hierarchy CD-011 | Fixed order only |
| R6 | **Contribution isolation**: server validates each contribution against a schema; malformed/failing contributions are dropped and recorded (error + observability event), others unaffected (FR-010) | Resilience | All-or-nothing manifest |
| R7 | **Breadcrumbs from route handles**: each route declares `handle.crumb` (label key + parent) and optional async label resolver (object name); contextual links via `handle.related` contributions (FR-012/013) | Declarative, i18n-ready | Computing from URL strings |
| R8 | **Always-reachable Search & AI**: shell reserves slots (`SearchEntry`, `AiEntry`) rendered independently of page data; they call APIs of 008/018 lazily; AI failure never blocks search (FR-016/017) | Contract-only now; engines come later | Embedding engines in shell |
| R9 | **Command Palette**: frontend command registry (destinations from navigation + actions from manifests + registered shortcuts); built on Radix Dialog + a combobox (`cmdk`-style, own implementation to keep a11y control); server marks each command available/unavailable via the same permission filter; fuzzy match local, global-search fallback later (008) | FR-019/020 | Server-only palette |
| R10 | **Keyboard shortcut catalog (OQ-16 default)**: baseline `Mod+K` palette, `/` focus search, `g` then letter go-to chords, `?` shortcut help, `Esc` close; user customization stored as user-tier config `shell.shortcuts`; shortcuts never active inside text inputs; no conflicts with assistive tech | Product input flagged | Fixed non-configurable |
| R11 | **Responsive**: CSS container/media queries + drawer navigation on small screens; same destination set on mobile (FR-022/023) | Design-system primitives (022) | Separate mobile app |
| R12 | **Global states via error/suspense boundaries per region**: `RouteBoundary` renders the standard functional states; `GlobalStatusBanner` shows degraded mode when a health summary (006/025 via API) reports multiple failing areas; core nav/search remain interactive (FR-026/027) | Isolation | One global error page |
| R13 | **Unauthorized vs not found (OQ-19 default)**: routes flagged `existence_sensitive` (object detail pages) show the same "not available" state for missing *and* forbidden; non-sensitive module destinations show explicit "unauthorized" (FR-028). Default pending product confirmation | Avoids existence leak | Always 403 or always 404 |
| R14 | **Authenticated-only shell (OQ-18 → CD-025)**: unauthenticated visitors see only the login/verify surface (002); shell never rendered | Canonical decision | Public shell |
| R15 | **Live updates**: shell subscribes to a single SSE stream (`/me/stream`, kernel) for `navigation.changed` (permission/module change) and refetches the manifest; also refetch on window focus (FR-030/032) | No polling storms | Polling only |

No `NEEDS CLARIFICATION` remains; R5, R10 and R13 are **plan defaults for open product questions** (OQ-16/17/19).
