# Research — Statistics (spec 017, roadmap step 14)

| # | Decision | Rationale | Alternatives rejected |
|---|---|---|---|
| R1 | **Definitions are declarative data** (`StatisticDefinition`, JSON-Schema validated, versioned) built from a **closed set**: measures `count|sum|avg|min|max|distinct_count`, dimensions declared as `aggregatable` fields in the 007 event-type registry, period/granularity options, visualization type, scope, unlock condition, privacy threshold. **No free query/expression language** | FR-001 (admin-defined, no BI builder), CD-010 (no second rules engine), safe/deterministic | Free SQL/query builder; scripting |
| R2 | **Computation = incremental projection** driven by a 007 consumer per active definition set: additive measures kept in **daily buckets** (`stats.buckets`); distinct measures in `stats.members` (exact, per day); idempotent through 007 `ctx.idempotent_effect(key=(stat, def_version, event_id))`; replayable via `ReplayService.rebuild` | FR-005/022, determinism, reconstruction | On-demand scans of the event store; streaming engine |
| R3 | **Time semantics (OQ-81 default)**: one **statistics time zone** (`statistics.timezone`, default `i18n.defaultTimeZone`) and `statistics.firstDayOfWeek` define bucket boundaries at **write time**; weeks/months/years roll up at read time. All consumers (dashboard, Wrapped, AI, gamification) get identical values for the same stat/scope/period (FR-017). Changing the zone triggers an audited rebuild | Deterministic cross-consumer values | Per-user tz (values differ per viewer; 30/45-min zones complicate hourly buckets) |
| R4 | **Definition versioning & history (FR-008/023)**: append-only `stats.definitions(key, version)`; buckets keyed by `definition_version`; change policy `forward_only` (default; history keeps values under the version in effect, as recorded in event payloads such as `rule_version`) or `rebuild` (admin-confirmed replay) | Historical truth of versioned rules | Always recompute |
| R5 | **Privacy-safe aggregation (OQ-82 default)**: every community/global statistic has `min_cohort_size` (default 5 distinct contributors); cells below threshold are suppressed (merged into "other" or state `insufficient_data`); personal statistics are owner-only unless the owner's visibility preference (021 `VisibilityFilter`, datum class `statistics`) allows sharing | FR-006/007/016 | No threshold |
| R6 | **Unlock conditions** = closed set evaluated through ports: `level_at_least` (013 `ProgressionReader`), `achievement_earned` (013), `product_owned` (015 `EntitlementReader`), `campaign_active` (014 `CampaignReader`), `all_of`/`any_of`. **Locked ⇒ nothing computed or returned for that principal** (response carries state `locked` + unlock hint only). Re-lock (OQ-83 default): `relock` flag per definition — `false` for level/achievement, `true` for campaign/product; evaluated at every access; permanent unlocks persisted in `stats.unlocks` | FR-012..014 | Evaluating in the client |
| R7 | **Cross-service statistics**: events carry `service_id` and a canonical entity reference (007/005 id-first dedup, CD-015); definition lists `sources[]` (service kinds/ids). At read time each source's health (006 `health.service_state`) and projection watermark yield `partial`/`stale`/`unavailable` with `as_of` | FR-010/011/021 | Silent omission of failed sources |
| R8 | **Provider interface (FR-015..017)**: `StatisticsProvider.get(stat_key, subject, period, viewer)` is the **single authoritative read path** used by dashboard widgets, gamification, campaigns, notifications/newsletters, Wrapped, AI tools, recommendations and leaderboards; always bounded by the viewer's permissions/privacy; consumers never read buckets directly | Consistency | Consumers computing their own aggregates |
| R9 | **Wrapped**: `WrappedDefinition` (ordered stat keys + period) generated by a job into an immutable per-user snapshot (`activity` personal data); delivery through the 010 `notifications.send` port honoring preferences (in-app page works without it) | FR-018/019 | Live-rendered recap only |
| R10 | **Freshness (OQ-84 default)**: projection target lag ≤ 1 min for hot definitions; `as_of` = consumer watermark; per-definition `stale_after_s` (default 900) drives `stale`; heavy ranges are served only from buckets (bounded bucket count per request), plus ETag/short TTL cache | FR-021/024 | Real-time on-demand computation |
| R11 | **Authorship (OQ-80 default)**: only the single Admin defines/edits definitions (`statistics.manage`, audited); plugins may ship definition packs that install **inactive** until the Admin enables them; domain specs ship built-in packs | CD-001/CD-023 | Editor-authored statistics |
| R12 | **Charts**: Recharts (SVG) wrapped in the 022 `Chart` component with mandatory accessible alternatives (data table toggle, text summary, patterns not color-only) and theme tokens | WCAG 2.2 AA, FR-004 | Canvas charts (poor a11y); a BI embed |

No `NEEDS CLARIFICATION` remains; R3, R5, R6, R10, R11 are **plan defaults for OQ-80..84**.
