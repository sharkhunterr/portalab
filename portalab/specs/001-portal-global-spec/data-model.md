# Data Model — Foundation Conventions & Kernel Entities (spec 001)

Scope: the **portal-wide data conventions** (roadmap step "Data") and the **few entities the kernel itself
owns**. Domain entities belong to their owning specs (see the ownership map) and are *not* redefined here.

## 1. Conventions (apply to every module)

| Concern | Rule | Source |
|---|---|---|
| Primary key | `id uuid` UUIDv7, generated by the application (`core.ids.new_id()`) | R7 |
| Instants | `timestamptz`, stored UTC; `timestamp without time zone` is forbidden (lint test) | CD-012, 026 |
| Occurrence facts | `occurred_at` (real occurrence) **and** `received_at` (portal receipt, default now). `received_at` is never an identity or dedup key alone | CD-012 |
| Row bookkeeping | `created_at`, `updated_at` (mutable tables only) | — |
| Schema | one PostgreSQL schema per module/plugin (`identity`, `events`, `config`, `connectors`, `media`, …) | R9 |
| Foreign keys | allowed **inside** a module, or to `identity.users(id)`; every other cross-module link is a logical id (no FK, no cross-schema join) | R9 |
| Append-only | event store, audit log, Coin/XP/Contribution ledgers, purchases: DB trigger rejects `UPDATE`/`DELETE`; corrections/refunds are new rows referencing the original | CD-005, CD-013 |
| Amounts | integers (`bigint`) — never floating point; rule/version id stored on each grant | CD-004/014 |
| Provenance | externally sourced rows: `source_system text`, `external_id text` (unique together), `provenance jsonb` (origin, observed_at, source version) | CD-014/026 |
| Disconnect/outage | never triggers row deletion; rows gain a derived `stale` state at read time | CD-014 |
| Versioned rules | tables holding rules/curves/campaigns carry `version`; facts reference the version in force at `occurred_at` | CD-004/012 |
| Personal data | every PII column is registered in the **classification registry** (§3); user references use `identity.users(id)` only | CD-016 |
| Visibility | personal/activity rows carry `visibility` governed by Privacy (021); default **not public** | CD-016 |
| Naming | snake_case, singular table names, `*_id` for references, enums as `text` + CHECK (no native PG enums) | convention |

## 2. Kernel entities (owned by `core`)

### `core.job` — durable background job / transactional outbox row
- **Purpose**: at-least-once, restart-safe execution of background work and event/notification delivery.
- **Fields**: `id` (UUIDv7) · `queue` (text) · `kind` (handler key) · `payload` (jsonb, no secrets) ·
  `dedup_key` (text, nullable; unique per `(queue, dedup_key)` when set — the *form* of event keys is defined by 007) ·
  `status` (`queued|running|succeeded|failed|dead`) · `run_at` · `attempts` · `max_attempts` ·
  `locked_by`/`locked_until` · `last_error` (redacted) · `created_at`/`updated_at`.
- **Lifecycle**: `queued → running → succeeded`; failure ⇒ backoff to `queued`, then `dead` after `max_attempts`
  (visible to Observability, replayable by an authorized admin).
- **Indexes**: `(queue, status, run_at)` partial on `queued`; unique `(queue, dedup_key)` partial.
- **Audit/retention**: succeeded rows pruned by retention policy (configured via Administration); `dead` kept until resolved.
- **Privacy**: payload references ids, never PII bodies. **Events**: emits nothing itself; handlers emit domain events.

### `core.schema_version` (provided by Alembic) — migration state; not a domain entity.

No other persisted kernel entity: the capability registry is **in-memory**, rebuilt at startup from loaded
modules/connectors; service *instances* are owned by Connectors (005); settings by Administration (020).

## 3. PII classification registry (metadata, not a table)

Each persisted model declares its personal-data columns with a class from Privacy (021): `identifier`,
`contact`, `profile`, `preference`, `activity`, `content`, `technical`. The registry is generated at import
time and exposes `personal_columns(model)` so that Privacy can implement **export**, **tombstone anonymization**
and **retention** generically. A CI test fails if a column named like PII (email, name, ip, token…) is not
classified or explicitly marked non-personal.

## 4. Deletion & anonymization pattern

```
active ──request──▶ pending_deletion (cancellable) ──grace ends──▶ tombstoned (terminal)
```
- Tombstone = `identity.users` row keeps `id` + `deleted_at`; PII columns nulled; credentials/sessions removed;
  `display_name` released (reuse allowed, no inherited history — OQ-8 default).
- Dependent modules keep rows that reference the tombstoned `user_id` (ledger, votes, purchases, history) —
  integrity preserved; their PII-class columns are scrubbed by the registry walk; aggregates untouched.
- Remaining Coins: a ledger `destruction` entry (never a refund/transfer) — owned by Gamification (013).

## 5. Migration conventions

- Single Alembic environment; each module/plugin contributes a `versions/` location and a branch label.
- Naming `YYYYMMDD_HHMM_<module>_<what>`; one concern per revision; revision must declare its schema.
- **Expand/contract**: add nullable/defaulted → backfill → switch → drop in a *later* release.
- Never alter or rewrite rows in append-only tables; backfills create new rows or use explicit, audited admin tooling.
- Required tests: upgrade from empty; upgrade from previous release with representative data; downgrade only
  in development.

## 6. Relationships (foundation level)

```
identity.users 1──n (any module's user-linked rows, via user_id)
core.job       n──1 queue/handler registry (in memory)
module schema A ··logical id··▶ module schema B   (no FK)
```
