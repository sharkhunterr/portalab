# Research — Automations / Rules Engine (spec 019, roadmap step 21)

| # | Decision | Rationale | Alternatives rejected |
|---|---|---|---|
| R1 | **Bounded linear model**: `trigger → condition tree → ≤ N sequential action steps` (default N = 10), per-step `on_error: stop|continue`, **no branching, loops or user code**. Params use closed substitution (`${event.field}`, `${subject.id}`) only | Non-goal "not an n8n clone", FR-001, safety | DAG/workflow engines; scripting |
| R2 | **Triggers are domain events** from 007 (any type flagged `automatable` in the event-type registry, including plugin/system events) plus **bounded time triggers (OQ-90 default)**: one-time `at`, `relative` (offset from a reference time carried by a source event, e.g. maintenance start − 1 h), and `recurring` limited to `daily|weekly|monthly @ HH:MM` in a time zone, minimum interval 1 h — **no cron expressions** | FR-010..012 | Free cron |
| R3 | **Conditions = closed catalog** combined with `all_of/any_of/not` (max depth 3), evaluated deterministically (order-independent): `user_is`, `role_in`, `level_at_least` (013), `service_state_in` (006), `media_kind/genre/title_contains` (014 `ActivityAttributeProvider` + 026 normalization), `campaign_active` (014), `time_window` (026), `permission_held` (003, informational — never grants), `event_field` comparators over declared attributes. The evaluator records a trace of each leaf | FR-013/014 | Free expressions; AI-evaluated conditions |
| R4 | **Actions are owned by domains**: each domain registers `ActionType{key, params_schema, required_permission, sensitivity, handler, idempotency}`; the engine only orchestrates. Baseline catalog (as owners land): `communication.produce` (010), `award.xp|coins|contribution` and `reward.unlock` (013 via an anti-abuse-bound `grant_via_automation`), `ticket.create`, `incident.create` (016), `content.publish` (011), `connector.sync`, `connector.action` (005), `status.update` (owner), `ai.invoke` (018, assist-only), `approval.request`, `automation.trigger` | FR-015..017, principle XX | Engine-owned implementations |
| R5 | **Identity & authoring (OQ-93 default)**: v1 authoring is **Admin-only**; automations run either as the **author** (`Principal(channel=automation, user=author)`) or a **scoped system identity** whose explicit permission scopes are validated at publish (≤ Admin's current rights) and enforced at run. Personal user automations are designed-for but disabled (`automations.allowUserAuthoring=false`); when enabled they are restricted to the author's own events/rights | FR-004..006 | Unbounded system identity |
| R6 | **Permission re-evaluation at run time** for every action; author deactivated or rights reduced ⇒ execution `refused` and automation flagged `needs_review`; actions never exceed the identity's current rights | FR-005 | Evaluate only at publish |
| R7 | **Sensitive/critical actions (OQ-92 default)** = the 018 sensitive catalog (deletions, permission/role changes, economy rule changes, refunds/large grants, destructive service/connector operations, configuration changes, plugin install/enable). They require an **`approval.request` gate**: *destructive* ones are approved **per execution** by an approver; *non-destructive* sensitive ones may carry a **standing approval** attested by Admin at publish (`ConfirmationService`). Critical outcomes are decided only by deterministic conditions — **AI output is never a condition input** and automations with sensitive actions cannot reference `ai.*` outputs | FR-007..009 | AI-decided gates |
| R8 | **AI-in-automation boundary (OQ-94 default)**: `ai.invoke` may *draft/summarize/classify into text fields* consumed by non-critical actions (e.g., notification body, ticket summary), under the author's rights with a read-only tool policy; never as a condition, never in sensitive actions' params, never auto-approving | FR-009/027 | AI as decider |
| R9 | **Loop prevention (OQ-91 default)**: every execution has `chain_id` (= 007 `correlation_id`) and `depth`; events emitted by actions carry `provenance.automation{id, execution_id, depth}`; engine refuses (`prevented(loop)`) when `depth ≥ automations.maxChainDepth` (3) or the automation already appears in the chain; `automation.trigger` uses the same mechanism | FR-018/019 | Global kill only |
| R10 | **Repeat prevention**: idempotency `(automation_id, version, trigger_event_id)` + optional `dedup_key` template with `dedup_window` (same logical occurrence fires once) + per-automation `cooldown` | FR-020 | Best effort |
| R11 | **Timeouts & storms (OQ-91 defaults)**: execution timeout 30 s (10 s per action) with cancellation; per-automation rate limit (60/min) and global concurrency cap; excess is **batched** (`batchable` automations coalesce into one execution with `batch_count`) or recorded as `throttled` — never silent | FR-021/023 | Unbounded fan-out |
| R12 | **Auto-suspension (OQ-91 default)**: ≥ 5 consecutive failures or > 50 % failures over 20 runs ⇒ `suspended` with reason + `automations.suspended` notification; explicit re-enable required; executions while suspended are recorded | FR-022 | Silent retry forever |
| R13 | **Execution history** `automations.executions`: status ∈ {success, no_op, refused, prevented, timeout, suspended, failed, throttled, awaiting_approval}, condition trace, per-step results, provenance — references and counts only (no event bodies, no secrets); retention 90 days; failures isolated per execution/job | FR-003/025/026 | Event-per-execution (storm) |
| R14 | **Authoring safety**: schema-driven builder from registries, validation at save (permissions, action params, depth), **dry-run** against sample/recent events (no side effects), version history (immutable), preset templates | Operability | Free-text authoring |

No `NEEDS CLARIFICATION` remains; R2, R5, R7, R8, R9, R11, R12 are **plan defaults for OQ-90..94**.
