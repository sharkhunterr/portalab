# Research — Media (spec 024, roadmap step 16)

| # | Decision | Rationale | Alternatives rejected |
|---|---|---|---|
| R1 | **Service-independent identity** = `media.objects` (UUIDv7) never deleted when a source disappears (only `availability` changes); external ids (`tmdb`, `imdb`, `tvdb`, `isbn`, `igdb`, …) live in `media.external_ids` and anchor matching | FR-002/005/034 | Using the source's id as identity |
| R2 | **Matching (OQ-115 default)**: **id-first** (CD-015): a source record sharing a strong external id with an existing object resolves to it; otherwise a new object is created and, if normalized title+year+kind score exceeds a threshold with no conflicting ids, a **match candidate** is queued for Admin confirmation (never silently auto-merged on fuzzy evidence). Merge/split by `media.manage`, audited and **reversible** (merged objects keep provenance; `merged_into` pointer) | Prevents irreversible wrong merges | Fuzzy auto-merge; per-source silos |
| R3 | **Per-field source priority (OQ-119/CD-026)**: all candidate values kept in `media.field_candidates` (per source); effective value chosen by the configured ordered list `media.fieldPriority.<kind>.<field>` (stored in 020 config; shape finalized here, consumed by 005), with Admin override as top-priority pseudo-source; effective values materialized on the object with `field_provenance` | Provenance never lost (CD-014), deterministic merge (FR-008) | Last writer wins |
| R4 | **Ingestion through 005**: Media registers `RecordSink`s for capabilities `media.library` (catalog/metadata/availability) and `request.service` (requests); sinks are idempotent on `(service_id, external_id)`, never delete (`removed` ⇒ `active=false`) | 005 contract, FR-006/007 | Media polling services itself |
| R5 | **Capability catalog introduced here**: `media.library` (sync only), `media.playback` (live: `now_playing(service)`, `recent_history(service, since)`), `request.service` (live: `submit`, `status`; sync: request records), `media.reading`/`media.games` expressed as `kind`s of `media.library` records (no provider-specific code in Core) | FR-006/007/014 | A Plex-shaped core model |
| R6 | **Playback = polled, normalized sessions**: a per-service poll job (default 15 s while any session is active, 60 s idle, adaptive) calls `media.playback.now_playing`; sessions are normalized to `PlaybackSession{session_key, user link, media_ref, state, position, duration, device, as_of}` and upserted in `media.playback_sessions`; state changes emit events; **progress events are throttled** (state change or ≥ 60 s); source loss ⇒ session `stale` then `interrupted` after a timeout | FR-013..016; bounded event volume | Webhooks as the only path (not all services support); event per poll |
| R7 | **User mapping** `media.user_links(user_id, service_id, external_user_id)` — created by the user (verification through the service when supported) or Admin; unmapped source activity is retained as *unlinked* and never attributed | Privacy/identity correctness | Matching on display name |
| R8 | **History**: the **event stream (007) is the record**; `media.history_entries` is a rebuildable query projection (continue watching, detail page, stats inputs). **Finished thresholds (OQ-116 default)** per kind in config: movie/episode 90 %, book 95 % or last page, track 80 %, game manual/explicit ending only | FR-017..019 | History only in tables |
| R9 | **Cross-source progress (OQ-117 default)**: unified resume point = entry with the greatest `occurred_at`; all per-source progress retained; *finished* is sticky and never regresses from older events; out-of-order handled by `occurred_at` | 005 source-of-truth, 007 ordering | Per-source only; last received wins |
| R10 | **Availability ⟂ service health ⟂ sync state (FR-033..035)**: three independent facts returned side by side — object availability (from active source items), `health.service_state` (006), last sync outcome (005) — never collapsed into one flag; outage never removes catalog entries | Spec requirement | Single "status" field |
| R11 | **Images**: stored via `core.blobstore` after fetching through the connector client; served by a Media image endpoint (no source URL/token ever reaches the client); size/type validated and re-encoded | FR-041 secrets, privacy | Hot-linking source URLs |
| R12 | **Requests**: `media.requests` mirror source requests (state machine normalized: pending/approved/declined/processing/available/failed/cancelled); creating goes through `request.service.submit` after quota check: base quota from config, extra quota via `RequestQuotaProvider` port (015) — **no paid priority** (queue order never depends on payment, CD) | FR-021..023 | Media owning payments |
| R13 | **Discovery (OQ-118 default)**: Media supplies the surfaces (new, recently watched, continue, trending, recommended) behind a `RecommendationProvider` port; baseline provider is deterministic (genre/people affinity from the user's history + popularity from 017 stat) — AI-powered providers plug in later (018) | Surface now, algorithm replaceable | Building ML here |
| R14 | **Extensibility**: `MediaType` registry, detail-page **slot registry** (declarative blocks, permission-gated), statistic packs (`media`, `playback`, `reading`, `gaming`) shipped to 017, widgets to 009, palette actions to 008, search provider to 008, event types to 007 | FR-004/012/036 | Hard-coded types/blocks |
| R15 | **Privacy**: personal history datum class `media_history` default Private (021); "concerned users" list shows only users whose visibility allows it; aggregate stats follow 017 cohort rules | FR-011/020/037 | Public by default |

No `NEEDS CLARIFICATION` remains; R2, R3, R8, R9, R13 are **plan defaults for OQ-115..119**.
