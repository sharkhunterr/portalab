# Research — Marketplace (spec 015, roadmap steps 25 · 26)

| # | Decision | Rationale | Alternatives rejected |
|---|---|---|---|
| R1 | **Two slices in one module**: *Slice A (step 25)* = community **funding lifecycle** (projects, reservations, validation gate, refund/consume, notifications) — the part Community depends on; *Slice B (step 26)* = **Marketplace** catalog, products, conditions, purchase, ownership, activation, refunds, grants, revocation, quota, audit | User roadmap (25 before 26), CD-008 | Splitting into two modules |
| R2 | **Funding lifecycle state machine (CD-008)**: `idea → proposal → open (votes free + funding reserved) → validation → development → beta → released`, off-ramps `rejected | abandoned`; Community owns proposals/votes, Marketplace owns state/funding; transitions are permissioned (`projects.*`), audited, append-only history, each emits `project.status_changed` | FR-021/024 | Lifecycle inside Community |
| R3 | **Funding = reservation in the ledger**: Gamification/Economy owns Coins; Marketplace calls `EconomyService.reserve(user, amount, source_ref)` → `release` (refund, new tx) on reject/abandon, `consume` on release (or per milestone) — **requires reservation operations in 013 (follow-up)**. Funds are never silently moved: only released or consumed per the **published per-project rules** fixed when the project opens | FR-023/025, CD-005/008 | Marketplace-owned balances/escrow |
| R4 | **Funding rules (OQ-71 default)**: `{refund_on_reject: 100 %, refund_on_abandon: 100 %, consume_at: "released" | milestones[{state, percent}], min_funding, max_funding_per_user, goal_amount (display only)}` set by Admin at `proposal → open`, **immutable once open** (changing requires abandon + refunds); every funding records an explicit acknowledgement that **funding does not guarantee implementation** (FR-026) | Transparency, protects funders | Mutable rules |
| R5 | **Voting/funding independence**: Marketplace exposes `ProjectLifecycle.accepts_votes` (states idea/proposal/open) and funding only in `open`; no coupling (votes counted in Community, funding in Marketplace) | CD-007 | Combined vote+fund action |
| R6 | **Account deletion (FR-031, default)**: reserved funds of a deleted user whose project is **already in development or later** stay committed and are consumed per the project rules (funder anonymized); funds for earlier states are **released then destroyed** with the account's Coins; owned products are tombstoned with the account | Respects project commitments and CD-005 | Refund to a deleted account |
| R7 | **Product model**: `marketplace.products` with extensible **ProductType registry** (`plugin, widget, statistic, theme, effect, badge, title, quota, feature, access` + `community_project` as the funding path), categories, per-product `version` rows (price/conditions/refund policy) so history is never reinterpreted; states `draft → available ⇄ unavailable → archived` (archived keeps owners' access); multilingual names/descriptions through 026 | FR-001..009 | Per-type tables |
| R8 | **Conditions (OQ-74 default)**: closed set — `free`, Coins price, `min_level` (013), `achievement` (013), `campaign_active` (014), `role` (003) — **strict AND** across all declared conditions; unmet conditions are listed by name; evaluated server-side at acquisition | FR-004/005 | OR groups; client-side checks |
| R9 | **Atomic acquisition**: `PurchaseService.acquire` runs in one DB unit of work: eligibility → duplicate/ownership check (unique `(user, product)` for permanent products, `repeatable` opt-in) → `EconomyService.spend(..., uow)` (013 follow-up: accepts the caller's unit of work, otherwise idempotent saga + compensating refund) → ownership row (snapshot of price/conditions/version) → outbox events; activation runs after commit and its failure never undoes ownership (state `needs_configuration | activation_failed`) | FR-006/010/011/013, CD-006 | Spend then best-effort ownership |
| R10 | **Activation through handlers**: each ProductType registers an `ActivationHandler` (widget → 009 entitlement filter; theme → 022 availability; statistic → 017 `product_owned` unlock; badge/title/effect → cosmetic ownership surfaced in profile sections; quota → `QuotaService`; plugin/feature/access → 023 `ExtensionActivation` and 003 scoped grants limited to an Admin-approved allow-list, never Admin-reserved permissions). **Ownership is per user; plugin code installation is portal-level done by the Admin when publishing** (flagged for confirmation) | FR-012/013, 023 | Portal-wide activation per purchase |
| R11 | **Quota (OQ-72 default)**: quota products add **extra request units** to a per-user, non-expiring `quota_units` balance consumed only after the free per-period base quota (024 config); implemented as `RequestQuotaProvider` for 024; **no paid priority anywhere** — priority/queue order has no input from ownership (contract test against 024's queue ordering) | FR-019/020 | Priority tiers |
| R12 | **Refunds (OQ-70 default)**: per product-version `refund_policy{refundable, window_days, percent}`; default `refundable=true, window_days=7, percent=100` for cosmetic/widget/theme/statistic/feature, **non-refundable** for plugin/access and for quota units already consumed; non-refundable is displayed before purchase; refunds are **new ledger transactions** referencing the original; refunding revokes the ownership | FR-015, CD-005 | Retroactive edits |
| R13 | **Grants & revocation (OQ-73 default)**: admin grants are marked `origin=grant` (optional expiry) and audited; **revocation grounds** are enumerated (`abuse`, `grant_expired`, `refund`, `withdrawn_for_cause`) with mandatory reason, audited, user notified; revoking a Coins-purchased product refunds per policy unless the ground is `abuse`; history never rewritten | FR-016/017/018 | Arbitrary revocation |
| R14 | **Audit & events**: every sensitive action (publish, price/condition change, archive, refund, grant, revoke, project validation/status/rule changes) → `AuditSink`; domain events `marketplace.purchase|unlock|refund|grant|revocation|product_published|product_archived`, `project.funding_added|funding_released|funding_consumed|status_changed` | FR-018/029 | Logging only |

No `NEEDS CLARIFICATION` remains; R4, R6, R8, R10, R11, R12, R13 are **plan defaults for OQ-70..74**; cross-plan follow-ups (013 reservations/uow, 009/022/017/024 readers, 023 activation) are listed in the plan.
