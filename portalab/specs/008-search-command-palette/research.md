# Research — Global Search & Command Palette (spec 008, roadmap step 11)

| # | Decision | Rationale | Alternatives rejected |
|---|---|---|---|
| R1 | **Federated live search**: each domain registers a `SearchProvider` that queries **its own tables** with the domain's authorization/visibility applied *inside the query*; a `SearchCoordinator` fans out in parallel with a per-provider time budget and merges grouped results | Source-of-truth freshness (OQ-37 default: read-your-writes for lexical), no cross-module data copy (001 boundaries), permissions enforced where data lives (CD-002, FR-015/016) | Central content index (duplicates data, stale ACLs, leak risk); external engine (Elasticsearch/Meilisearch — new infra, PostgreSQL-only baseline) |
| R2 | **Lexical engine = PostgreSQL FTS** (`tsvector` generated columns + GIN, `websearch_to_tsquery`) + `unaccent` + `pg_trgm` for typo tolerance/prefix; per-language text-search configuration chosen from the document language (026) | Zero new infrastructure, adequate at personal/community scale | Elasticsearch/OpenSearch; naive `LIKE` |
| R3 | **Semantic retrieval = pgvector** in a derived table `search.embeddings(kind, id, language, vector, content_hash, visibility_epoch)` filled by an outbox job through an **`EmbeddingProvider` port** (optional; none by default; may be implemented by AI 018 or a local model). **The vector table holds ids+vectors only; candidates are re-hydrated and re-authorized by the owning provider at query time** | FR-006/007; index never authoritative for permissions (OQ-37); AI/embedding optionality (CD-021) | Semantic via LLM per query (slow, non-deterministic); no semantic support |
| R4 | **Graceful semantic degradation**: without an `EmbeddingProvider`, "semantic" mode falls back to trigram + synonym/stem expansion and the group reports `semantic: unavailable` honestly (never silently pretending) | FR-002/023 honesty | Hiding the limitation |
| R5 | **Classic ∥ AI = two independent requests**: `POST /search` (REST, synchronous result groups with per-group state) and `POST /search/assist` (SSE stream from the AI port). No shared failure path; UI renders each independently | FR-001..005, plan 001 §4 | One combined stream |
| R6 | **AI port** `SearchAssistant.stream(query, principal, result_refs) -> events` declared here, implemented by 018; output events typed `source_ref` (real data) vs `synthesis` (interpretation) so the UI can distinguish (FR-005); the assistant receives only references the principal may see and runs under the principal's rights (CD-003/FR-017) | Boundary with 018 | Embedding AI logic in search |
| R7 | **Query model**: parsed into `{text, filters{type, dateRange, owner, tags, status…}, language, mode}`; filter facets declared by providers; relative time ("this week") resolved with the user's `LocaleContext` (026: tz, first-day-of-week) — OQ-36 default | FR-010/011 | Free-text-only |
| R8 | **Search history** table, per user, private, capped (default last 50, 90 days) and clearable (single/all); personal data class `activity`; disabled by a user preference `search.historyEnabled` | FR-019..021, OQ-38 default | Storing history in events |
| R9 | **Usage events carry no raw query**: `search.performed` holds `{user_id, result_counts_by_type, took_ms, mode}` and a salted hash of the query only when statistics need dedup; AI never receives the history unless the user asks | FR-030, privacy | Raw queries in the event store |
| R10 | **Command Palette backend**: `ActionCatalog` (declared actions with `sensitivity: normal|sensitive|destructive`, required permission, optional `confirmation_required`), `ObjectResolver` registry (`portalab://kind/id`, short references), `IntentResolver` (deterministic grammar first). Frontend palette from 004 extended — no second palette | FR-024..029, OQ-39 default | Palette owning its own registry |
| R11 | **Natural language**: deterministic intents resolve locally and instantly (navigate/search/known commands with aliases per language); unresolved text is *also* sent to `SearchAssistant.interpret()` in parallel and returned as **suggestions only** — the palette never executes an AI-interpreted action without an explicit user selection and normal authorization/confirmation | FR-028, CD-003 | AI auto-execution |
| R12 | **Sensitive actions** invoke the owning module endpoint with a `ConfirmationService` token (003) and are audited by the owner; the palette is only a launcher | FR-029, CD-013 | Palette-side execution |
| R13 | **Abuse/perf controls**: query length cap, per-user rate limit (021 limiter), per-provider timeout (default 1500 ms) and result caps, parameterized queries only (no query-string-to-SQL), result snippets HTML-escaped with highlight markers | Security/availability | Unbounded fan-out |
| R14 | **Defaults for open questions** (config-backed): OQ-35 AI limited to synthesis over classic results plus sources the principal is permitted to use through its normal tools; OQ-37 lexical results are live, semantic is eventually consistent (target index lag < 1 min) and always re-authorized; OQ-38 history 90 days/50 entries; OQ-39 baseline action list in data-model | Flagged for product confirmation | Hard-coding |

No `NEEDS CLARIFICATION` remains.
