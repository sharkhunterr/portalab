# Research — AI Capability (spec 018, roadmap step 18)

| # | Decision | Rationale | Alternatives rejected |
|---|---|---|---|
| R1 | **Authorization is enforced in code, never by the model.** The AI acts as `Principal(user=U, channel="ai")`; `authorize()` never widens for non-user channels (003). The tool list shown to the model is filtered by the user's permissions **and** every tool call is re-authorized at execution | FR-001/002, CD-003 | Trusting the model's judgement; a service account for the AI |
| R2 | **Tools are thin wrappers over the same domain service functions the human API uses** (no parallel path): owners register `AITool{name, description, params_schema, required_permission, sensitivity, handler}` through `register_ai_tool`; handlers call the domain service with the AI principal so business rules, events (`actor_kind=ai`, `acting_for=U`) and audit are identical (FR-015) | No second business-logic path | AI-only endpoints |
| R3 | **Tool sensitivity classes**: `read`, `write` (non-sensitive, e.g. create a draft), `sensitive` (needs confirmation), `ai_forbidden` (never executable by AI). **Sensitive catalog (OQ-86 default)** = actions whose permission is flagged sensitive in the 003 registry plus: deletions, permission/role changes, economy-rule changes and refunds/Coin grants above a threshold, destructive service/data operations, configuration changes, plugin install/enable. **AI-forbidden**: Admin transfer, secrets/credential viewing or changes, AI provider/tool configuration itself, audit/event store mutation | FR-013, 003 sensitive actions | A free-form model-decided sensitivity |
| R4 | **Out-of-band confirmation**: a sensitive call never executes inline; it creates `ai.pending_actions{id, tool, params, params_hash, summary (generated by the tool from structured params, not by the model), expires_at}`. The UI shows a confirmation card; only the user's own session (`POST /ai/actions/{id}/confirm`, CSRF, step-up when 003 requires) issues the `ConfirmationService` token and executes with idempotency; expiry/decline ⇒ nothing runs; params bound by hash so the model cannot alter them after confirmation | FR-013/014/024 | Model-asked "are you sure?" in chat |
| R5 | **Prompt-injection defenses (FR-003)**: (a) authorization/confirmation independent of model output; (b) all tool results enter the context as **untrusted data** with provenance, never as instructions (system prompt + structured tool-role messages); (c) no generic network/exfiltration tool; model output rendered through the sanitized Markdown pipeline (external images blocked, link rel); (d) per-turn tool-call and loop budgets; (e) secret redaction on tool inputs/outputs; (f) cross-user content (wiki, tickets, comments) flagged untrusted; (g) a regression **injection corpus** in CI | Defense in depth | Prompt-only mitigation |
| R6 | **Provider abstraction (OQ-85 default)**: `LLMProvider` port with declared capabilities (`tools`, `streaming`, `max_context`, `json_mode`) and a conformance kit. Baseline adapter = **OpenAI-compatible Chat Completions** (works with hosted APIs and local servers such as Ollama/vLLM/LM Studio), configured by Admin (endpoint, model, secret key); native adapters can be added without core changes. **No model is chosen by the portal** | FR-023, self-hosted friendly | Binding to one vendor SDK |
| R7 | **Streaming over SSE** with typed events (`delta`, `tool_call`, `tool_result` (summary), `source`, `pending_action`, `error`, `done`); classic search runs independently (008) — the AI is a separate request and failure domain | FR-008, FR-022 | WebSocket; blocking responses |
| R8 | **Source attribution (OQ-88 default)**: per-answer sources list **and** inline `[n]` markers that the server validates against sources actually retrieved in the turn (invalid markers dropped). Each source carries a class `real` (current state, with `as_of`), `historical`, or `knowledge`; uncited prose is rendered as *interpretation*; partial/stale/unavailable tool results are surfaced as caveats | FR-016/017 | Free-form citations |
| R9 | **Conversations** (`ai.conversations`, `ai.messages`) are **owner-only** personal data (`content`), sliding-window context with token budgeting, retention default 90 days, user-deletable, erased with the account; admins see only aggregate metrics, never content. No long-term memory in v1 | FR-004/007/027, privacy | Admin-readable transcripts |
| R10 | **MCParr and other MCP servers** via an `ExternalToolSource` adapter (MCP client over HTTP transports using the official `mcp` SDK; MCParr also exposes an OpenAPI tool endpoint). **Default-deny mapping**: only tools explicitly allow-listed by the Admin, each mapped to a portal permission + sensitivity, are exposed; calls are authorized by the portal before leaving; failure/absence ⇒ the tool simply isn't offered (FR-021). Trust boundary (OQ-87 default): MCParr is a configured **service** with credentials in `core.secrets`; it never receives portal session tokens | FR-019..021 | Exposing all MCP tools; making MCParr mandatory |
| R11 | **Cost/abuse controls**: `ai.use` permission, per-user rate limit and daily token budget, concurrency cap, request timeouts, global kill switch (`ai.enabled`) | Availability/cost | Unbounded usage |
| R12 | **Audit detail (OQ-89 default)**: sensitive AI actions audited with `actor_kind=ai`, `acting_for=user`, tool, redacted params (+hash), confirmation id/time, conversation/message **ids** (never prompt text), result; non-sensitive AI writes carry `actor_kind=ai` in the domain's own events/audit | FR-015/025, privacy | Storing prompts in audit |
| R13 | **Embedded integrations**: implements `SearchAssistant` (008: `stream`, `interpret`), executes 016's `DiagnosisFlow` with a fixed read-only tool subset producing only a ticket **draft**, and may supply the optional `EmbeddingProvider` for semantic search | Port contracts already planned | Parallel implementations |
| R14 | **Navigation (FR-010)**: `navigate.suggest` tool returns permitted route refs from the 004 navigation view; the UI renders them as links/buttons (auto-navigation off by default, setting `ai.autoNavigate`) | Safety and a11y | The model emitting raw URLs |

No `NEEDS CLARIFICATION` remains; R3, R6, R8, R10, R12 are **plan defaults for OQ-85..89**.
