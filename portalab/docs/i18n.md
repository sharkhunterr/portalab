# Internationalization (spec 026)

Portalab separates four independent choices for every user:

| Axis | Setting (user / global) | Drives |
| --- | --- | --- |
| Interface **language** | `i18n.language` / `i18n.defaultLanguage` | which catalog messages are shown |
| Formats **locale** | `i18n.locale` / `i18n.defaultLocale` | dates, numbers, units, currencies, sorting |
| **Time zone** | `i18n.timeZone` / `i18n.defaultTimeZone` | how instants are displayed and wall-clock schedules fire |
| Clock and week | `i18n.hourCycle`, `i18n.firstDayOfWeek` | overrides of the locale's defaults |

The server resolves them into a `LocaleContext` (`GET /api/v1/i18n/context`); the SPA never guesses.
A preference for a language the administrator disabled is **kept** (`retained_language`) and applies
again once the language is re-enabled.

## Message keys and catalogs

- Base bundles live in `backend/locales/<language>/<namespace>.json` (flat `{key: message}`), shared by the
  backend renderer and the SPA (which bundles the English files as its last-resort fallback).
- Namespaces: `core`, `nav`, `shell`, `i18n`; plugins use `plugin.<key>` (and sub-namespaces) only.
- Keys are stable identifiers (`nav.services`, `paletteResults`) — never English sentences.
- Administrators can override a message (`PUT /api/v1/admin/i18n/catalog-entries`, permission
  `i18n.manage`); overrides are validated (ICU syntax, same placeholders as the source) and audited.
- The effective catalog is *base ⊕ plugin bundles ⊕ published overrides*, served per namespace with an
  `ETag` equal to its content hash.

## Writing messages (ICU MessageFormat)

- Always use arguments, never concatenation: `"Hello {name}"`, not `"Hello " + name`.
- Counts use plurals: `{count, plural, one {# result} other {# results}}` — languages have different
  plural categories (Polish, Russian, Arabic…), so give at least `other`.
- Use `select` for gendered or variant text and `selectordinal` for ranks.
- Markup is not interpreted: a message is plain text.
- A missing argument renders as `{name}`; a missing key renders the fallback chain's value (then English,
  then the key) and is counted in `i18n.missing_key_stats` — rendering never fails.

Backend: `module.renderer.t("key", ctx, {"count": 2}, namespace="shell")` (pure-Python ICU renderer with
Babel plural rules — see `docs/spikes/i18n-backend-renderer.md`). Frontend:

```tsx
const t = useT();
t("shell:paletteResults", { count: results.length });
const format = useFormat(); // format.date(), .time(), .dateTime(), .number(), .percent(), .relative()
```

Both sides pass the same golden vectors (`backend/tests/data/icu_vectors.json`).

## Checks

```bash
cd backend && uv run portalab i18n check     # ICU validity, placeholder parity, missing/unused keys
cd frontend && npm run i18n:check            # the same rules with the SPA's parser (formatjs)
uv run portalab i18n extract                 # keys referenced by the sources
```

Both run in the CI `validate` stage.

## Pseudo-locales

- `en-XA`: accented, lengthened text (`[Ñàvîgàtîöñ ~~~]`) — reveals hard-coded strings and truncation.
- `ar-XB`: right-to-left text — reveals layouts that do not mirror.

In development, open the SPA with `?pseudo=en-XA` or `?pseudo=ar-XB`; `uv run portalab i18n pseudo`
writes pseudo bundles. `frontend/tests/e2e/i18n/rtl-pseudo.spec.ts` checks both in CI. Layout uses CSS
logical properties, so `dir="rtl"` mirrors it.

## Adding a language

1. Add `backend/locales/<code>/*.json` with every key of the English bundles (`i18n check` lists the
   missing ones).
2. Insert the language row (`i18n.languages`: code, native and English names, direction) with a migration.
3. Enable it: `i18n.enabledLanguages` (global setting). Disabling it later keeps users' preferences.

## Plugin catalogs

A plugin ships `{language: {"plugin.<key>": {key: message}}}` in its manifest's `i18n` section. Bundles
are validated (ICU syntax, own namespace only — a plugin can neither override portal strings nor change
the default language) and withdrawn when the plugin is disabled or removed (`plugin.state_changed`).
Missing plugin translations fall back like any other message.

## Operator settings

| Setting | Default | Notes |
| --- | --- | --- |
| `i18n.defaultLanguage` | `en` | must be enabled |
| `i18n.enabledLanguages` | `["en", "fr"]` | must include the default |
| `i18n.fallbackChain` | `["en"]` | acyclic |
| `i18n.defaultLocale` | `en` | |
| `i18n.defaultTimeZone` | `UTC` | IANA zone |
| `i18n.unknownLanguagePolicy` | `show_as_is` | `show_as_is` or `hide` for content with no declared language |
| `i18n.ambiguousTimePolicy` | `gap_forward\|overlap_earlier` | DST gaps and overlaps |
| `i18n.schedulingDefault` | `absolute` | `absolute` or `wall_clock` schedules |

Health: `GET /api/v1/admin/i18n/health` (fallback rate per language, missing keys, bundle load failures).
